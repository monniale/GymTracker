# ROUTEMAP — GymTracker module index

Purpose: a compact map of the codebase so a fresh chat can **load only the files a task needs** instead of scanning `src/`. Line counts `(N)` flag context cost. Paths are relative to repo root.

**Stack:** React + TypeScript + Vite + Tailwind, Dexie/IndexedDB, `HashRouter`. Ships as a **static PWA on GitHub Pages — no backend.** Cross-device sync is a snapshot pushed to a **private GitHub repo via the user's PAT**. AI is a **device-local BYO key**: Gemini free tier (default), any OpenAI-compatible server (OpenAI, OpenRouter, Groq, Mistral, local Ollama / LM Studio) or Claude. Deploy = `git push origin main` → Actions → Pages. The same codebase is also a **sideloaded Android app (Capacitor 8)**: `android/` + `src/native/`, runbook in `ANDROID.md`.

Build/verify: `npm run build` (= `tsc --noEmit && vite build`) + `node scripts/check-pwa-dist.mjs` · CI: `.github/workflows/ci.yml` runs both tsc configs, `npm test`, `node scripts/build-programs.mjs --check`, the Pages build + `check-pwa-dist` and `vite build --mode android` on every PR and feature-branch push; `deploy.yml` runs `npm test` + `check-pwa-dist` before deploying · `npm test` (vitest, `TZ=Europe/Rome`, English locale pinned) · Node 18 floor / CI Node 22 · Android: `npm run android:debug` / `scripts/android/release.sh` / `scripts/android/smoke.sh` (Node ≥ 22, JDK 21, SDK 36) — see ANDROID.md.

## Cloud sync (Supabase)
Row-level deltas with server-side last-write-wins; the GitHub snapshot below stays as a backup. Project URL + anon key come from `VITE_SUPABASE_URL`/`VITE_SUPABASE_ANON_KEY` (public by design; RLS = `user_id = auth.uid()`); unset → `cloudConfigured()` false and the feature is hidden. Schema + setup notes: `supabase/migrations/0001_rows.sql` (one `rows(user_id, tbl, id, data jsonb, updated_at, deleted, server_seq)` table, `push_rows(jsonb)` upsert that keeps the newer `updated_at`).
- `src/db/outbox.ts` (81) — the cloud outbox: `queueOutbox(table, key, updatedAt, deleted)` from the Dexie middleware on every tracked add/put/delete (`LOCAL_ONLY_TABLES` = AI caches + tombstones skipped), `pendingOutbox`, `ackOutbox` (an entry re-queued during its push keeps its newer `updatedAt`, so nothing is lost), `clearOutbox`; localStorage `gymtracker-cloud-outbox` (a user transaction scoped to two tables could not write an IndexedDB outbox).
- `src/lib/supabaseConfig.ts` (12) — `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `cloudConfigured`.
- `src/lib/supabaseApi.ts` (140) — plain-`fetch` client (no SDK): GoTrue `requestOtp`/`verifyOtp` (email + 6-digit code: the Magic Link template must include `{{ .Token }}`)/`refreshSession`/`signOutRemote`; PostgREST `pushRows` (rpc `push_rows`), `pullRows` (`server_seq > cursor`, pages of 1000), `listLiveIds`; `SbError` kinds auth / bad-code / rate-limit / paused (540/503: free project paused) / network / other.
- `src/lib/cloudSync.ts` (345) — `useCloudStore` (zustand persist `gymtracker-cloud`: session, `lastSeq` cursor, `lastSyncAt`; device-local, invariant 3), `cloudSignIn`/`cloudVerify`/`cloudSignOut`, `cloudSyncNow` = pull (`applyCloudRows`: a cloud row wins when `updated_at ≥` the local `updatedAt`, a tombstone deletes + writes a local tombstone; barcode clashes on the unique `offId` settled by `dedupFoodsByOffId`, the loser deleted on the cloud and its logs remapped) → `fixAfterPull` → push the outbox in chunks of 500 → pull the echo; on the `withSyncLock` chain, `'demo'` while demo data is loaded, never rejects. `cloudInitialSync('merge' | 'use-cloud' | 'overwrite-cloud')` for a device that signs in with data (overwrite stamps every local row past the cloud's clocks and deletes cloud-only rows). `CLOUD_TABLES` = backup `TABLES` minus tombstones.
- `src/lib/cloudFixups.ts` (61) — after a pull: `dedupAwards` (one quest award per `date|label`, earliest kept), `recomputeRank` (`rankPointsFor`), `remapFoodIds`; tracked writes, so they sync back.
- `.github/workflows/keepalive.yml` — daily REST ping so the free project is not paused (secrets `VITE_SUPABASE_URL`/`VITE_SUPABASE_ANON_KEY`; repo variable `SUPABASE_KEEPALIVE=off` disables it).

## Invariants (read before schema / sync / scoring / AI changes)
1. **Sync allow-list is `backup.ts` TABLES** (mirrored in `merge.ts` `SnapshotTables`; the cloud sync uses it minus `tombstones`: `CLOUD_TABLES`). A table syncs **iff** it's listed there, and a row reaches the cloud **iff** its write went through the tracked middleware (the outbox). Device-local AI caches (`coachNotes`, `dietNotes`, `workoutSuggestions`, `dietSuggestions`) are **deliberately excluded** — never add them. Stored coach verdicts are user data in their own table (`coachHistory`, synced). A table added after snapshot v2 goes in `LATE_TABLES` too and is optional in `SnapshotTables`, so a snapshot from an older build (missing it) never wipes it.
2. **AI cache writes** must be wrapped in `withSyncTrackingSuspended` and use natural keys (not in `UUID_TABLES`). Real user-data writes (sessions/sets/foods/rank… and stored coach verdicts in `coachHistory`) must **not** be suspended. One exception: the stored `SetRow.e1rm` of a stamped session's row is derived (exercise + session), so `refreshStampedE1rm`/`healStampedE1rm` rewrite it suspended (a fresh `updatedAt` would resurrect a deleted workout's sets or beat a real set edit in a merge) and every device re-derives it after `applyTables`. `withSyncTrackingSuspended` nests.
3. **The AI key and base URL (any provider), the GitHub PAT, the Supabase session and all device-local prefs (notifications, haptics, rest-alert mode, language) never touch Dexie** — they live in zustand-persist stores in localStorage (`gymtracker-ai`, `gymtracker-sync`, `gymtracker-cloud` (+ `gymtracker-cloud-outbox`), `gymtracker-notify`, `gymtracker-ui`, Android `gymtracker-update`), so they are never synced or backed up.
4. **Every structured AI call goes through `engine.generateStructured<T>`** with `aiRequestOpts()`. Gemini sets `generationConfig.thinkingConfig.thinkingBudget=0` (Flash otherwise truncates JSON) and retries the free-model fallback chain; its fallbacks are free Flash/Flash-Lite models only (a billed key must never silently pay for a Pro fallback). OpenAI-compatible servers and Claude use the chosen model only, with one retry after 2 s on rate-limit / 5xx / blocked / empty / truncated / unparseable answers (the only other model is Anthropic's own server-side refusal fallback on the Claude models that have it, `usesServerFallback`, disclosed in Settings); the app never adds a paid fallback. The engine sets no token cap unless a feature asks for one: each provider keeps its default (Gemini 2048, Claude 16000 because thinking shares the budget, OpenAI-compatible servers their own). A rejected key, a permission error on the chosen model, no network (incl. a provider or SDK chunk that fails to load, mapped to `AiError` 'network') or an abort never falls back or retries. Every provider gets the localized system prompt.
5. **`finishSession` is non-idempotent** (adds a scoreEvent, adds full points, bumps streak). To re-score an edited past workout use **`rescoreSession`** (updates the existing event, applies only the points delta, carries the streak).
6. **Equipment separation is by `exerciseId`** — variants are distinct exercises; no `SetRow.equipment`. Every weight/PR/progression path already partitions by exerciseId. **Cardio rows** are SetRows with `durationSec > 0` and `weightKg/reps/e1rm = 0`, so strength paths skip them; test cardio with `isCardioSet`/`isCardioExercise`. **Bodyweight load is forward-only:** on a session stamped `Session.bwScoring` (new sessions from `WorkoutHome.startWorkout` and every import) a non-cardio `equipment === 'bodyweight'` set's `weightKg` is ADDED kg (negative = assisted) and its load is `effectiveLoad` = `bodyweightKg × bwFactorOf(ex) + weightKg` (stored in `SetRow.e1rm` via `setE1rm`); unstamped sessions keep load = `weightKg`, so `rescoreSession` reproduces old totals. Every load/volume/PR read goes through `src/lib/load.ts` (`effectiveLoad`/`toScoreSets`/`withLoads`/`fmtSetLoad`), never `weightKg` alone. `gatherSeasonPriorBests` ignores `e1rm <= 0` priors for a stamped session (no fake first PR), reads stamped prior rows live (`setE1rm`, the current `bwFactor`/equipment, like the scored session) and never mixes stamped and unstamped rows of a bodyweight exercise; `planImportScoring` applies the same stamp split (`existingSets[].bwScoring`). `bwFactor` belongs to the exercise: a change applies to every stamped workout (`refreshStampedE1rm`, and `healStampedE1rm` on the other devices after a pull/merge), earned points stay until that workout is re-scored. The pull-up strength standard rates only bodyweight-load sets. AI weight plans keep negative (assisted) kg for bodyweight-load exercises (`snapWeight` floor −bodyweight). `muscleVolume`/`muscleHeat` count sets, not kg. **Set type is metadata, never a scoring filter:** drop / failure / AMRAP sets (`SetRow.setType`; absent = working, never stored as 'working'; warm-up stays `isWarmup`, read the kind with `setKind`) and `SetRow.rpe` count for points, volume, hard sets, PRs and rep maxes exactly like working sets; only `progression.ts` and the coach briefings read them. Known risk: a build before cardio shows such a row as "0 kg × 0" and its set editor can write weight/reps onto it (`durationSec` survives the update). Known risk (snapshot version is still 2, so nothing stops it): a build before `bwScoring` (e.g. an APK not yet updated) that edits a stamped workout re-scores it at `weightKg` (added kg: a plain bodyweight set scores 0, synced back) and its stepper clamps assisted kg to 0; this build re-derives the e1rm of those rows on the next pull, but the points stay until the workout is edited again here. Update the APK together with the web build.
7. **Food dedup key** is the derived `offId = barcode ?? source:sourceId` (OFF stays bare EAN → backward-compatible; USDA branded reuses the EAN; whole foods → `usda:<fdcId>`).
8. **Dexie schema is additive** — bump `version(N)` with only new stores; never edit a released version block (current: 10). Seed uses **deterministic ids** (id: i+1) so two fresh installs merge without duplicating the catalog; seed rows carry `updatedAt: 0` (written suspended), so a real row always wins a merge. Exercises added from the library also get a deterministic id (`lib-<dataset id>`, tracked write) so the same pick on two devices merges into one row; exercises are never deleted, so no tombstone can block a re-add.
9. **Deletes that must propagate** use `deleteWithTombstone`/`tombstoneKeys`; device-local cache deletes use a plain suspended `delete()`.
10. **Routing:** `HashRouter`; parse ids with `parseRouteId`, never `Number()`. **Ordering:** `orderBy('date'/'startedAt')`, not `orderBy('id')` (UUID strings don't sort chronologically).
11. **Report mode** (`?report=1`) must skip `checkAchievements`/`evaluateQuests`/confetti/rank-up (side-effects wrong for old sessions).
12. **Env/CI:** Node 18 floor / CI Node 22 for the PWA; Android tooling needs Node ≥ 22 (`@capacitor/cli` 8.5.2) and JDK 21 with `javac`; Capacitor packages are pinned exactly (the committed `android/` must match); `workbox-build` 7.1.1 override; self-hosted assets only (no CDN — zxing wasm + fonts bundled). One opt-in exception: the exercise-library animations/thumbnails (© Gym visual, not ours to redistribute) load from `raw.githubusercontent.com/hasaneyldrm/exercises-dataset/<pinned sha>/` only when Settings › Exercise library is on (off by default), with the credit shown, cached by the SW (thumbs ≤ 600, GIFs ≤ 80 entries); never copy that media into the repo. USDA key: `VITE_USDA_KEY` (inlined into the public bundle at build — only OK because it's a free per-IP-rate-limited key). Build stamp: `vite.config.ts` `define`s `__APP_VERSION__` (package.json), `__BUILD_SHA__` (`GITHUB_SHA` → local git), `__BUILD_TIME__`; typed in `src/vite-env.d.ts`.
13. **Phone widths:** every screen must hold at **360px** (Galaxy S25) and **320px** with no overflow. Two+ `NumberStepper`s in one row → `compact="narrow"` + `flex-wrap`; chips/badges/short buttons get `whitespace-nowrap` (+ `shrink-0` in flex rows) so they move as a unit instead of breaking onto 2 lines; names `truncate`. Fixed-px widths in a row must sum under ~290px. On Android the WebView text zoom is pinned to 100% (`setTextZoom(100)` in `MainActivity`), so these rules hold whatever the One UI font size.
14. **Native/PWA split.** Plugin packages (`@capacitor/*` except `@capacitor/core`, `@capacitor-community/*`, `@capacitor-mlkit/*`) are imported only in `src/native/**`. Outside `src/native/`, code may statically import only `native/platform.ts` and `native/haptics.ts`; everything else is a dynamic `import()`/`React.lazy` gated on `isNative` (compile-time false in the Pages build, so Rollup drops the chunks). Native-only UI lives in `src/native/ui/`. Enforced by `nativeBoundary.test.ts` + `scripts/check-pwa-dist.mjs`. The Pages build keeps SW, manifest and base `/GymTracker/`; `dist-android/` is never deployed.
15. **Identity is permanent.** `appId = io.github.monniale.gymtracker`, WebView origin `https://localhost` (never set `server`/`hostname`/`androidScheme`), release key in `~/.android-keys/gymtracker/` (never in the repo). Changing any of them orphans or wipes the phone's data. Debug/emulator builds (`….debug`) must never connect to the real sync repo (`smoke.sh` aborts).
16. **Notification IDs.** LocalNotifications ids = `cat*10_000_000 + dayIdx*100 + slot` (`dayIdx` from 2026-01-01); planner cats 10–18 (`isManagedId`), 99 = test reminder. RestTimer owns Android ids 4201 (countdown) / 4202 ("Rest over") and PendingIntent request codes 4211–4215; it never goes through LN. The widget tap uses request code 4301. Every alerting notification except the countdown sets an app group (`gt_reminders`, `gt_rest`; no summary): Android 16 force-groups ungrouped ones and, on its base release, silences them. Never make 4201 a group summary (it blocks Live Update promotion). Never call `LocalNotifications.removeAllDeliveredNotifications()` (it cancels everything, incl. the rest countdown).
17. **Channels are immutable.** Ids carry `_vN`; to change sound/importance/vibration, bump the id and delete the old one: reminder channels via `OBSOLETE_CHANNELS` in `native/notifications.ts`, rest channels in `RestTimerController.ensureChannels` (also update the ids mirrored in `native/ui/notifyHealth.ts` and `smoke.sh`).
18. **LocalNotifications discipline.** Only one-shot `schedule.at` with `allowWhileIdle: true` and an explicit `isExactNotification`; never `on`/`every`/`repeats`; never `schedule()` without notifications granted + enabled (no implicit prompt, no Alarms & reminders bounce); never a time ≤ now + 30 s (`LEAD_MS`); never `cancel({ notifications: [] })`. Notification taps only navigate (whitelisted routes), never write data or call `finishSession`.
19. **All UI copy goes through `src/i18n`** (`t`/`tp`; `stringGuard.test.ts` fails on literal JSX text or aria-label/placeholder/title/alt). Every Italian key must exist in English and keep its `{placeholders}` (`i18n.test.ts`). **Stored data stays English**: catalog exercise names (shown via `exerciseDisplayName`), score-event labels (`displayEventLabel`), `Season.finalRank` (`rankLabelEn` stored, `translateRankLabel` shown), quest `labelEn`. Text sent to the AI provider as data stays English; only the model's answer language follows the UI. Default names the user owns and can edit (a new template, a freestyle session, a saved meal) are written in the UI language: they are user content, not app data. Changing the language reloads the app and, on Android 13+, sets the per-app locale so Java strings follow it.

20. **Demo data never syncs.** While `uiStore.demoLoaded` is true, `doSync` returns `'demo'` before any network call, the write/foreground triggers do nothing, and `connect`/`previewConnection` throw `data.sync.demoLoaded`. The guard reads `demoLoadedAnyTab()` (another tab's saved flag counts). The demo is never loaded on a connected device or over user data (`canOfferDemo`, re-checked in `loadDemoData`); clear forgets `lastSyncedSha` so a connected device pulls rather than pushes. Load and clear leave the device clean (`setSyncDirty(false)`) and run on the sync lock; only `clearDemoData` and `importBackup` turn the flag off. A CSV import is refused while the demo is loaded (`applyImport`): clearing wipes every table, rows added over the demo included, and the clear confirms say so. The demo option is web-only; Android keeps its RestoreCard.

21. **Program progression state** lives only in `TemplateItem.progress` and `Exercise.trainingMaxKg`, applied once per workout by `finishSession` (`applySessionProgression`, after the scoring transaction, idempotent per `progress.lastSessionId`; a TM bump at most once per cycle per item, `progress.tmCycle`; a linear lift's progress is shared by the program's lines with the same exercise + scheme; a line rewritten to another exercise or swapped in a session never carries the old exercise's progress); `rescoreSession`, report mode, `PastWorkout` edits and imports never apply it. It syncs with its template (same LWW exposure as any item edit). Preset and shared exercise names stay English (shown via `exerciseDisplayName`); share files never carry progress, ids, weekdays or the cycle start. Shared links always open the Pages build (`/import` is not a native route).
